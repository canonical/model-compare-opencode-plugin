# OpenTUI 0.6.8 + @opencode/plugin 2.1.4 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Land the OpenTUI 0.6.8 and `@opencode/plugin` 2.1.4 upgrade in two staged PRs and close issue #11.

**Architecture:** Stage 1 moves the OpenTUI devDependencies to `0.6.8` and widens the peer range to `>=0.5.8 <0.7.0`, keeping `@opencode/plugin` at `2.0.32`. Stage 2 moves the plugin to `2.1.4`, adds `@opencode/theme@2.1.4` as a devDependency, narrows the peers to `^0.6.8`, and fixes the footer status line's colour type. Stage 1 is independently mergeable; stage 2 follows on top of it.

**Tech Stack:** npm, Node 20 (CI), Vitest, TypeScript, Solid JSX via `@opentui/solid`, OpenCode 2.1.4 host via `@opencode/cli`.

**Spec:** `docs/superpowers/specs/2026-10-26-opentui-0.6.8-plugin-2.1.4-design.md`

## Global Constraints

- Target OpenTUI `0.6.8` exactly in both stages.
- Stage 1 peer ranges: `@opentui/core` and `@opentui/solid` at `>=0.5.8 <0.7.0`.
- Stage 2 peer ranges: `@opentui/core` and `@opentui/solid` at `^0.6.8`.
- `solid-js` peer stays `^1.9.0`; `solid-js` devDependency stays `1.9.12`.
- The `overrides.seroval` entry stays `^1.6.9` and `tests/unit/dependency-pin.test.mjs` stays unchanged.
- `@opencode/plugin` stays `2.0.32` in stage 1 and becomes `2.1.4` in stage 2.
- `@opencode/theme` is a devDependency only in stage 2, at `2.1.4`.
- No version bump per stage. One release, `0.5.0`, after stage 2, only on explicit maintainer approval.
- OpenTUI `0.7.0` is out of scope (issue #13). The peer ranges must reject it.
- Every stage gate runs: `npm ci`, `npx vitest run tests/unit tests/conformance`, `npx tsc --noEmit`, `node scripts/build-tui.mjs`, `node scripts/pack-smoke.mjs`.
- The integration suite command is `MC_INTEGRATION=1 npx vitest run tests/integration`; it needs `opencode`, `python3`, and for one case `sqlite3` and network.
- The TUI smoke host is `@opencode/cli@2.1.4`, run with `OPENCODE_CONFIG_DIR=/tmp/opencode/empty-config` from a checkout outside this repository.
- Do not change CI's Node version in this plan. `@opentui/core@0.6.8` declares `engines.node >=26.4.0`; the resulting `EBADENGINE` warning is dev-only (the host runs Bun) and is documented rather than fixed here.

## Review Focus

1. Installing the packed plugin into an OpenTUI `0.5.17` host: the install must resolve after stage 1, not `ERESOLVE`.
2. Installing into an OpenTUI `0.6.8` host: the install must resolve after stage 1, and this is the generation the 2.1.x host uses.
3. Installing into an OpenTUI `0.7.0` host: the stage-2 peer range must reject it rather than silently accept an untested renderer.
4. The footer status line renders `context.theme.text.base` (an `RGBA`) without a TypeScript error and with the theme's colour, not a fallback.
5. The lockfile moves only the intended packages: no unrelated version drift in either stage, and `zod` stays absent after stage 2.
